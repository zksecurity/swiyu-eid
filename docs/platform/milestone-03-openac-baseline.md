# Milestone 03 — OpenAC real-proof baseline

Task id: `m03-openac-baseline`  
Profile: `swiyu-age18-status-2k-v0`  
Circuit: `swiyu_age18_status_2k`  
Inspected: 2026-09-15

## Verdict

Complete for the milestone. OpenAC's fixed Swiyu age/status circuit can run through the current integration and testing stack on a laptop, without a phone. The provider prepares the credential with the OpenAC SDK, presents a real proof through the SDK wallet and native backend, verifies it with verifier-supplied public inputs, and rejects a tampered challenge.

The scope remains narrow. This milestone does not audit OpenAC's proof system, prove that the circuit's statement is the intended statement, or solve wallet-side key management. It verifies that the declared OpenAC integration path can run, fail closed on wrong context, and be exercised by the platform test harness.

## Artifact contract

The provider requires explicit artifact roots for `present` and `verify`:

| Env root | Relative path | Purpose |
|----------|---------------|---------|
| `SWIYU_OPENAC_ARTIFACT_ROOT` | `assets/swiyu_age18_status_2k.wasm` | Circom witness calculator |
| `SWIYU_OPENAC_KEYS_ROOT` | `keys/swiyu_age18_status_2k_proving.key` | Spartan proving key |
| `SWIYU_OPENAC_KEYS_ROOT` | `keys/swiyu_age18_status_2k_verifying.key` | Spartan verifying key |
| `SWIYU_OPENAC_KEYS_ROOT` | `target/release/swiyu-profile` | Native prove/verify CLI |

The provider normalizes env roots before calling the native backend, so relative roots and `..` segments do not pass readiness and then fail later for path-shape reasons.

The local milestone signer is `inputs.holderPrivateKeyHex`. That keeps the current laptop-only host-prover path simple. A wallet callback or key-handle signing interface remains future work.

## Build commands used

```bash
cd components/zkid/wallet-unit-poc/circom
yarn install
yarn compile:swiyu

cd ../openac-sdk
npm run build:wasm
npm run build

cd ../ecdsa-spartan2
cargo build --release --no-default-features --bin swiyu-profile
cargo run --release --no-default-features --bin swiyu-profile -- setup keys
```

The first attempt to build `swiyu-profile` with default features failed because the `native-witness` feature expects a generated C++ witness directory. The corrected build uses `--no-default-features`; this is compatible with the provider because the SDK produces the `.wtns` witness.

## Grok 4.6 review findings closed

A Grok 4.6 read-only review found two integration blockers before the real proof run:

1. The provider loaded `WitnessCalculator` from `dist/swiyu-zkp/index.js`, but that class is exported from the SDK root entry. The provider now imports the SDK root entry for witness generation.
2. Artifact env roots were joined without normalization. The provider now resolves env roots before readiness checks and native backend calls.

Both findings have regression tests in `integration/providers/openac/tests/provider.test.mjs`.

## Remaining boundaries

This milestone demonstrates integration, not cryptographic assurance. It does not audit Spartan/OpenAC, prove the semantic statement is the intended statement, or certify the circuit. Those remain audit and contributor-review responsibilities. It also keeps phone hardware and Android emulation out of the critical path; the real proof path runs locally through the host-prover stack.
